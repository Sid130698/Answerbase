Architecture record · local implementation · November 2026

One product. Explicit access boundaries.

The customer application and Answerbase staff console are separate deployments. Both reach the Java API, which authorizes every operation before accessing workspace data. Supabase proves identity; Answerbase decides organization, workspace and document access.

Reading the arrows

Two arrowheads mean request and response, or read and write access; they do not imply symmetric trust. Dashed lines show background queue processing. Browsers never receive database credentials, model provider keys or unrestricted storage access.

Query path

Customer question → API authorization → query embedding → authorized latest-version vector and full-text retrieval → reciprocal-rank fusion → optional cross-encoder → incremental generation → complete-claim quote verification and current-access check → streamed claims → persisted answer and source citations. Failed verification clears drafts before retry/abstention. Provider outages use a durable bounded retry queue. Supabase is not involved in answering the question after token verification. Saved citations are rechecked against current document permissions.

Operational boundaries

Support access
The staff console issues scoped support grants and embeds the real customer application in a cross-origin sandboxed iframe with delegated access. The product UI is not duplicated. The server retains the staff actor for audit and applies the target user's permissions.
Workspace isolation
One shared database. Organization and workspace IDs are carried through foreign keys and authorization predicates. A missing workspace membership means no access. Document groups further restrict sources inside an accessible workspace.
Evaluation
The local runner is a development client, outside the production request path. It creates isolated fixture workspaces and calls the same APIs. Reports distinguish machine proxies from human-reviewed quality.
Storage lifecycle
Metadata removal and a deletion outbox are transactional; the worker retries physical object removal. Original documents remain available for authorized source inspection until deleted. Embeddings never replace originals.
Deployment status
Local containers, streaming, monitoring and backup/restore checks are exercised. Terraform and production Compose configuration are validated. Hosted authentication, storage, Groq, DNS/TLS and external alert delivery require real accounts. Current local generation does not meet the PRD latency targets.
